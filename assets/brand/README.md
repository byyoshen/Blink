## 派生方法（与具体画稿无关，下次照做即可）

无论用哪套画稿，发布资产都不能把母版直接丢进去 —— 母版是"展示稿"，主体只占画面
74–87%，浅色那张还不居中。实际处理：

1. **裁到徽章边界，再向内缩 10px** —— 不缩的话，徽章自身的抗锯齿白边会被包进来，在成品
   里表现为一条 255 亮度的细线（实测出现在 512² 输出的第 10–11 行与 499–501 行）。
2. **用徽章底色补成正方形** —— 底色要从徽章**左边缘中点**取；从角上取会落在圆角之外的
   白画布上（这个坑踩过一次，两个徽章都取成了纯白）。
3. **圆形要烘进 alpha**（4× 掩膜降采样做抗锯齿），不能靠 CSS。
4. 横幅只需缩到 1280 宽。

## 几条硬约束

- **方形 logo 必须满幅**：portal 渲染成 24px 圆形（`rounded-full` + `object-cover`），带白
  画布会在圆里出现白环，主体还会被进一步缩小。
- **圆形必须烘进 PNG**：GitHub 会剥掉 README HTML 里的 inline style，浏览器也不会自己把
  favicon 切圆。
- **favicon 与 og:image 用 PNG**：浏览器对 WebP favicon 支持不一致；链接预览抓取器对 WebP
  同样参差，一个悄悄渲染失败的预览比一个大文件更糟。
- **平涂 + 渐变的画稿用 WebP**：PNG 压不动（横幅 1280 宽要 351 KB），WebP q90 只要 11.5 KB
  且字标边缘无伪影。**含小字的 UI 截图相反，应保持 PNG** —— 文字边缘正是有损压缩最容易
  露馅的地方。
- **favicon 256² 足够**：页面只声明 `rel="icon"`，没有 apple-touch-icon 也没有 PWA manifest，
  没有任何消费者会请求更大的尺寸。
- 浅色徽章与白画布只差 2 级灰度，用普通亮度阈值找边界会直接误判成熊；要用贴近底色的阈值。
